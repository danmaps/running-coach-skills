# Race Prep

Own the season's target: choosing the race, understanding the course, and arriving at the start line prepared.

## Choosing a race

1. Take the constraints from the athlete profile: goal distance, date range, travel distance the user accepts, surface preference (road or trail), and terrain the user's training can support.
2. Search for candidate events from official event pages. Verify for each: date, distance, location, course profile (elevation gain and shape), surface, and entry status or cost when listed.
3. Compare candidates against the user's actual training context: a hilly trail course and a flat road course demand different plans, and the course profile must be checked, not assumed from the event name.
4. Present the shortlist with the tradeoffs and a recommendation tied to the user's goal. The user picks; write the pick into the athlete profile and the plan document.

## The countdown

- Phase the plan backward from race day with the plan-builder skill: build, peak (longest runs 3 to 4 weeks out), taper (reduced volume, kept rhythm, roughly 2 to 3 weeks for longer races, shorter for shorter ones), race week.
- Race week checklist: logistics (packet pickup, start time, travel, parking), gear laid out, weather check for race morning, and the race-day plan below.

## Race-day plan

- Pacing: set an effort-based plan from the user's recent training (long run pace and effort, recent workout data). Start controlled; the first portion should feel easier than goal effort. Never promise a finish time; give a pacing range and the reasoning.
- Fueling and hydration: standard guidance for the distance, practiced in training first. Nothing new on race day.
- Course notes: where the climbs, descents, and aid stations are, from the official course info gathered earlier.

## Guardrails

- Verify all event facts on official pages, and say when a fact (like a course profile) could not be confirmed.
- Standard guidance only. No medical clearance judgments; that belongs to the user's clinician.
