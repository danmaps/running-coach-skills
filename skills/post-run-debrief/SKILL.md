# Post-Run Debrief

Read and apply the [shared coaching rules](references/coaching-contract.md) before proceeding.


## Process

1. Read the profile, plan's dated session ledger, observations, adjustments log, and the linked journal entry if one exists and reading is permitted by the shared journal-preference rules. Find the accepted target in effect before the run. Do not reconstruct it from chat if the saved ledger differs; surface the discrepancy.
2. Retrieve the activity using the shared data rules. Match by saved activity ID or local date; resolve multiple plausible matches before attaching a run. For an unplanned run, say that no prescription exists instead of inventing a target.
3. Compare distance or duration and effort with the accepted prescription. Distinguish moving and elapsed time and account for terrain and stops before interpreting pace or splits. Do not infer subjective exertion from pace or heart rate alone.
4. Ask for missing subjective information when useful: how it felt, pain, or anything unusual. Record the athlete's report in their terms without making up a response.
5. Give one short takeaway for the next session. A single good run does not justify progression; symptoms may warrant an immediate pause regardless of the ordinary trend rule.
6. Save a factual observation keyed by session and canonical activity ID, including source aliases. Update it on a repeated review, preserving corrections. Mark a confirmed matched session completed without changing its prescribed target. Propose future target changes separately and save only accepted changes.
7. Check the shared journal-preference rules before journal work: update automatically during this review only for `after runs`; for `off` or `on request`, write only if the athlete explicitly asks for journal work now. An existing journal or a normal debrief request is insufficient. When writing is authorized, draft or update the linked entry with the confirmed objective snapshot and the athlete's subjective report. Follow the running-journal fields and upsert rules; leave unreported fields unknown instead of copying guesses into the journal. The plan observation remains the structured review record, while the journal holds the fuller context and takeaway.

## Output

Give planned vs actual, one supported observation, reported feel if known, and the implication for the next run. Keep the tone even and avoid disappointment or hype.

## Guardrails

Do not diagnose or wait for persistent symptoms before applying the shared symptom exception. Recording a debrief does not authorize changing future training.
